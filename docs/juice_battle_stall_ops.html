GAME CONTROL
game Trigger game over manually (announces winner, shows overlay)
$ curl -s -X POST http://localhost:5000/game_over | python3 -m json.tool
game Reset Jar 0 (Lemon Warrior) score to zero
$ curl -s -X POST http://localhost:5000/reset/0 | python3 -m json.tool
game Reset Jar 1 (Melon Crusher) score to zero
$ curl -s -X POST http://localhost:5000/reset/1 | python3 -m json.tool
game Adjust glass count — Jar 0: +1 (correct a missed pour)
$ curl -s -X POST "http://localhost:5000/adjust/0/1" | python3 -m json.tool
game Adjust glass count — Jar 0: -1 (undo a false pour)
$ curl -s -X POST "http://localhost:5000/adjust/0/-1" | python3 -m json.tool
game Adjust glass count — Jar 1: +1
$ curl -s -X POST "http://localhost:5000/adjust/1/1" | python3 -m json.tool
game Adjust glass count — Jar 1: -1
$ curl -s -X POST "http://localhost:5000/adjust/1/-1" | python3 -m json.tool
Note: adjust commands do NOT trigger glass.mp3 — by design. They are developer corrections, not real pours.
AUDIO CONTROL
audio Silence everything (mute USB speaker at hardware level)
$ amixer -c 0 sset Speaker 0%
audio Restore audio to working volume
$ amixer -c 0 sset Speaker 90%
audio Check what volume is currently set
$ amixer -c 0 sget Speaker
audio List ALSA mixer controls (if Speaker doesn't work, check what name to use)
$ amixer -c 0 scontrols
audio List all ALSA sound cards (USB adapter should be "Device")
$ aplay -l
audio Quick audio sanity check — plays a test tone
$ speaker-test -c 2 -t wav # Ctrl+C to stop
Why muting at hardware level works: pygame → SDL2 → ALSA → hardware. amixer talks to the ALSA mixer directly. pygame keeps running and playing — it just produces silence at the speaker. Full resume with one command.
SERVICE MANAGEMENT
service Restart game service (also triggers kiosk auto-reload within ~3s)
$ sudo systemctl restart juice-battle
service Check game service status
$ sudo systemctl status juice-battle --no-pager
service Restart BLE scanner service
$ sudo systemctl restart juice-ble-scanner
service Check BLE scanner status
$ sudo systemctl status juice-ble-scanner --no-pager
service Restart both services (scorched-earth recovery)
$ sudo systemctl restart juice-ble-scanner && sleep 2 && sudo systemctl restart juice-battle
Restart order matters: scanner first, then game. Scanner must be listening on TCP :7001 before game's transport client tries to connect.
LIVE LOGS
logs Watch all game events — pours, scoring, announcements
$ journalctl -u juice-battle -f
logs Watch game logs — filtered to audio and pour events only
$ journalctl -u juice-battle -f | grep -E "AmbientPlayer|SoundPlayer|POUR_SETTLED|announcement"
logs Watch BLE scanner — node connect/disconnect events
$ sudo journalctl -u juice-ble-scanner -f
logs Last 50 lines of game log (post-mortem, not live)
$ journalctl -u juice-battle -n 50 --no-pager
BLE / NODE DIAGNOSTICS
BLE Check which JB nodes BlueZ currently knows about
$ bluetoothctl devices | grep JB
BLE Check if BlueZ is actively scanning
$ bluetoothctl show | grep -i "discover\|scanning"
BLE Is the scanner's TCP port open?
$ ss -tlnp | grep 7001
BLE Force BlueZ to scan — use if a node won't appear after 30s
$ bluetoothctl scan on & $ sleep 15 && bluetoothctl devices | grep JB
BLE Verify transport host config (must be 127.0.0.1, not Docker IP)
$ grep "TRANSPORT_CLIENT_HOST" ~/arduino_apps/juice-battle/hub/config.py
Node won't connect — checklist:
1. LED on? → 2. Power cycle node → 3. bluetoothctl devices | grep JB → 4. Force scan above → 5. sudo systemctl restart juice-ble-scanner → 6. Check node isn't paired to another device (laptop BT)
KIOSK / DISPLAY
kiosk Step 1 — always do this first in any SSH session before using xdotool
$ export DISPLAY=:0 # must export — inline DISPLAY= does NOT cross pipe boundaries
kiosk Bring game screen back to front (focus stolen by another window)
$ export DISPLAY=:0 $ WID=$(xdotool search --name "Juice Battle" | head -1) && xdotool windowactivate $WID
kiosk Force Chromium kiosk to reload the page
$ export DISPLAY=:0 $ xdotool search --name "Juice Battle" | head -1 | \ xargs -I{} bash -c 'DISPLAY=:0 xdotool key --window {} ctrl+r'
kiosk Check Chromium window is visible (returns window ID if found, blank if not)
$ export DISPLAY=:0 $ xdotool search --name "Juice Battle"
kiosk Open ops reference HTML on the screen (this file)
$ DISPLAY=:0 chromium ~/ArduinoApps/juice_battle/docs/juice_battle_stall_ops.html
kiosk Navigate Chromium back to game dashboard (after viewing ops page)
$ export DISPLAY=:0 $ WID=$(xdotool search --onlyvisible --class chromium | head -1) $ xdotool key --window $WID ctrl+l # focus address bar $ xdotool type --window $WID "http://localhost:5000/v3" $ xdotool key --window $WID Return
kiosk Kill Chromium entirely and relaunch kiosk (nuclear option)
$ pkill -f chromium $ sleep 2 $ DISPLAY=:0 chromium --kiosk --noerrdialogs --disable-infobars http://localhost:5000/v3 &
Why DISPLAY=:0 must be exported, not just inline: When you write DISPLAY=:0 xdotool ... | xargs ..., the inline assignment only applies to xdotool on the left of the pipe. xargs runs in a new subshell with no DISPLAY. Always export DISPLAY=:0 first, then all subsequent commands in that session inherit it automatically.
